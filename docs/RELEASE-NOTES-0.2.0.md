# Tibo Watch 0.2.0

发布日期：2026-08-23

Tibo Watch 0.2.0 是面向个人体验测试的 V2 源码更新。本次更新重新组织了监控、历史审计、Codex 自动化和设置界面，并加强了重置预测、预存重置卡统计与本地安全边界。当前仍不提供正式 Release 安装包。

## 监控主页

- 采用白色、扁平化的本地控制台界面，减少重复说明和装饰性提示。
- 默认窗口根据屏幕可用区域自动确定大小并居中，常见桌面分辨率可直接容纳完整主页。
- 最新消息与统计区域使用左右各半布局；消息保持固定高度并在内部滚动。
- 最新消息只展示规则命中或 AI 判定相关的候选，避免无关回复刷屏。
- 顶部状态区区分“数据检查”和“最近重置”，避免把数据源轮询时间误认为重置时间。
- 预测时间到达后，以预测时间建立推定重置基线；Tibo 发布确认帖后，再以帖子真实发布时间覆盖并重新计算下一周时间。
- 已兑现或过期的预测不再持续覆盖新的周重置基线。

## 重置卡统计

- 读取 Codex App Server 提供的预存重置卡数量和可用明细。
- 展示当前可用数量、近 28 天使用次数、近 28 天过期次数、最早过期时间和最近使用时间。
- 官方返回 `expiresAt` 时优先采用官方时间；缺少明细时才按 4 周有效期进行保守推断。
- 可根据非周期窗口内额度从低位恢复到高位、卡片数量变化等信号推断重置卡使用，并标明确认或推断来源。
- 重置卡采样独立于历史回填和 AI 初始化，应用启动后立即读取，此后每 5 分钟刷新；本地观察记录保留 35 天。

## 规则与 AI

- 未配置 AI 时继续提供规则筛选、通知、Webhook 和保守自动化。
- AI Provider 与 OpenAI/Codex 账户授权保持解耦。
- 内置 DeepSeek 预设，并支持 OpenAI Responses、OpenAI Chat Completions 和 Anthropic Messages 兼容接口。
- 自定义 Provider 只发送跨协议的基础参数，结构化结果失败时不会凭空创建重置事实。
- 历史初始化只复核最近一周内的规则候选，并支持批量分析以减少请求次数。

## Codex 自动化

- 应用启动后自动探测 Codex CLI/App Server，并扫描 Desktop 与 CLI 共用的本地任务。
- Codex 页面改为任务浏览器、任务操作抽屉和自动任务列表。
- 每个任务可单独设置重置后执行、预测前执行、提前小时数、目标消耗、最低保留额度、动作和提示词。
- 支持限制单个周期最多启动的任务数量。
- 立即继续与自动执行分离：手动操作不要求开启自动化总开关，自动执行仍要求逐任务授权。
- 遇到 active writer 或正在运行的任务时拒绝追加指令；额度门禁只阻止新任务，不暂停、终止或降低正在运行的任务。
- 新增 `scan-codex-tasks.cmd`、`npm run scan:codex` 和专用恢复测试会话入口，方便诊断桥接状态。

## 数据、通知与安全

- 基础自检使用隔离的小样本，不写入真实历史、事件和统计。
- 无关回复保留 7 天，无关原创和引用保留 14 天；候选、事件和审计长期保留。
- 支持 Windows、飞书和通用 HTTP Webhook，并可按事件类型独立选择渠道。
- API Key、Webhook 秘密、自定义请求头和 Codex 授权继续保存在 Windows 凭据管理器。
- 保留 V2 本地数据迁移备份、非敏感数据导出和运行时边界检查。

## 已知限制

- 当前仅支持 Windows 本地单应用。
- 目前只监控 `@thsottiaux`。
- 自动化依赖本机可启动的 Codex CLI/App Server；WindowsApps 中不可直接执行的别名仍需要独立 CLI 桥接。
- 自然语言控制自动恢复、用户主动交互和正式安装版发布留待后续版本。
- 预测时间到达只建立推定基线；最终事实仍以 Tibo 确认帖或可验证的额度信号为准。
